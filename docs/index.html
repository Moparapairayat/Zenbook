Introduction

ZenBook is a production-ready, full-stack social networking platform built with React 18, TypeScript 5, Vite 5, Tailwind CSS v3, and powered by Supabase (PostgreSQL, Auth, Storage, Edge Functions, Realtime). Designed and maintained by WRAPCODERS.

👥
Social Networking

Posts, stories, reels, friends, groups, pages, events, and real-time messaging.

🛒
Marketplace

Buy & sell with listings, offers, seller reviews, verified sellers, and fraud detection.

🎬
Watch & Reels

Video platform with playlists, live streaming indicators, likes, and comments.

🛡️
Admin & Moderation

Full admin panel with user management, content moderation, CMS, and site design.

💰
Credits & Advertising

Credits economy with top-up, gifting, sponsored posts, boost pages/posts/listings.

🔐
Enterprise Security

Row-Level Security on 50+ tables, RBAC roles, content reports, user warnings & bans.

📖 How to Read This Documentation Follow sections 1–6 in order for a fresh install. If you're upgrading an existing installation, skip to Upgrade & Migrate. For feature details, see Core Features and Monetization.
🏢 Built by WRAPCODERS ZenBook is designed, developed, and maintained by WRAPCODERS. For support, custom development, or licensing inquiries, visit our website.

2. Install & Setup

Follow these steps in exact order for a fresh installation:

  1. Clone the Repository
    Terminal
    git clone https://github.com/your-org/zenbook.git
cd zenbook
  2. Install Dependencies
    Terminal
    # Recommended (fast)
bun install

# Alternative
npm install

    This installs ~80 packages including React, Tailwind, Supabase SDK, Leaflet, Recharts, and shadcn/ui components.

  3. Configure Environment Variables

    See Step 3: Environment Variables below for the full list.

  4. Run Database Migrations

    If self-hosting with your own Supabase, apply all migrations from the supabase/migrations/ folder:

    Terminal
    # Link your Supabase project
supabase link --project-ref YOUR_PROJECT_REF

# Push all migrations
supabase db push
    ℹ️ WRAPCODERS Cloud Users If you built this project on the WRAPCODERS platform, migrations are applied automatically. Skip this step.
  5. Start the Development Server
    Terminal
    bun dev    # or: npm run dev

    Opens at http://localhost:8080 (Vite dev server with HMR).

  6. Run the First-Run Wizard

    On first launch, you'll be redirected to /setup. See Step 4.

✅ Quick Start Summary git clone → bun install → configure .env → supabase db push → bun dev → /setup

3. Environment Variables

Create a .env file in the project root. Variables prefixed with VITE_ are exposed to the client bundle.

Required Variables

Variable Status Description Example
VITE_SUPABASE_URL Required Your Supabase project API URL https://xxxx.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY Required Supabase anon/public key (safe for client) eyJhbGci…
VITE_SUPABASE_PROJECT_ID Required Project ref ID (used for edge function URLs) abcdefghijklmnop

Optional Variables

Variable Status Description Default
VITE_DEMO_MODE Optional Enable demo/test mode with quick login panel (see Demo Mode) false

Backend Secrets (Supabase Edge Functions)

These are set in your Supabase project dashboard (or WRAPCODERS Cloud → Secrets), not in .env:

Secret Purpose
SUPABASE_SERVICE_ROLE_KEY Admin-level API access for edge functions (setup-admin, etc.)
LOVABLE_API_KEY AI features (translation, etc.) — auto-set on WRAPCODERS Cloud

Example .env File

.env
VITE_SUPABASE_URL="https://your-project.supabase.co"
VITE_SUPABASE_PUBLISHABLE_KEY="eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
VITE_SUPABASE_PROJECT_ID="your-project-ref"

# Optional: Enable demo mode (shows quick login panel on Auth page)
# Set to "true" for staging/demo, remove or set "false" for production
VITE_DEMO_MODE=false
⚠️ Security Never commit .env to Git. The .gitignore already excludes it. Only VITE_-prefixed values reach the browser — never put service role keys in VITE_ variables.

4. First-Run Wizard

The Setup Wizard runs automatically on first visit when no Super Admin exists. It creates your admin account and configures the platform.

Automatic Routing

Condition Behavior
No admin in user_roles table All routes redirect to /setup
Admin exists, user not logged in Protected routes redirect to /auth
Admin exists, user logged in Normal app access based on role

Wizard Steps

  1. Step 1 — Create Super Admin

    Enter display name, email, and password (min 8 chars, confirmed). The account is created via a secure setup-admin edge function with auto-confirmed email and admin role assigned server-side.

  2. Step 2 — App Identity

    Configure site name, description, URL, and upload branding (light logo, dark logo, favicon). Assets stored in the site-assets storage bucket.

  3. Step 3 — System Settings

    Toggle user registration, email verification, maintenance mode, and select default language.

  4. Step 4 — Review & Launch

    Summary of all config. Click "Launch Application" → sets setup_complete flag → redirects to home page.

🚨 One-Time Only Once setup is complete, /setup redirects to /auth. The edge function blocks duplicate admin creation. To re-run setup, delete the admin row from user_roles and the setup_complete setting from site_settings.

Nginx Configuration (VPS)

nginx.conf
server {
    listen 80;
    server_name yourdomain.com;
    root /var/www/zenbook/dist;
    index index.html;

    # SPA fallback — critical for client-side routing
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Cache static assets aggressively
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2?)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # Security headers
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
}

Upgrade & Migrate — Overview

When a new version of ZenBook is released, you need to update three layers:

🖥️
1. Frontend

Pull latest code, install deps, rebuild, and redeploy the static bundle.

🗄️
2. Database

Apply new SQL migrations to add tables, columns, RLS policies, and functions.

⚡
3. Edge Functions

Deploy updated or new serverless functions.

⚠️ Always Backup First Before upgrading, export your database and take a snapshot of your current dist/ folder. See Rollback Procedure.

Frontend Update

For WRAPCODERS Cloud Projects

Frontend updates are automatic when you click Publish → Update. No manual steps needed.

For Self-Hosted / GitHub-Synced Projects

  1. Pull the Latest Code
    Terminal
    cd zenbook
git pull origin main

# If using ZIP download: extract new version
# Keep your .env file — don't overwrite it
  2. Install Updated Dependencies
    Terminal
    rm -rf node_modules
bun install   # or: npm install
  3. Check for New Environment Variables

    Compare your .env against the changelog or the Environment Variables section.

  4. Build and Test Locally
    Terminal
    npx tsc --noEmit   # Type-check first
bun run build      # Production build
bun run preview    # Preview locally
  5. Deploy

    Upload the new dist/ folder to your hosting provider (see Deployment section).

Database & Backend Update

Each release may include new SQL migrations in supabase/migrations/.

For WRAPCODERS Cloud Projects

Database migrations are applied automatically. No manual steps needed.

For Self-Hosted Supabase

  1. Review New Migrations
    Terminal
    ls -la supabase/migrations/
cat supabase/migrations/YYYYMMDDHHMMSS_migration_name.sql
  2. Apply Migrations
    Terminal — Option A: Supabase CLI
    supabase link --project-ref YOUR_PROJECT_REF
supabase db push
    Terminal — Option B: Manual SQL
    psql "postgresql://postgres:YOUR_PASSWORD@db.YOUR_REF.supabase.co:5432/postgres"
\i supabase/migrations/YYYYMMDDHHMMSS_new_migration.sql
  3. Verify Schema
    SQL
    SELECT tablename FROM pg_tables WHERE schemaname = 'public' ORDER BY tablename;
SELECT tablename, rowsecurity FROM pg_tables WHERE schemaname = 'public' AND rowsecurity = true;
🚨 Migration Order Matters Always apply migrations in chronological order (sorted by filename timestamp). Never skip a migration.

Rollback Procedure

Frontend Rollback

Terminal
rm -rf dist/
cp -r dist-backup/ dist/

# Or revert via git
git checkout HEAD~1
bun install && bun run build

Database Rollback

🚨 Database rollbacks are destructive SQL migrations cannot be automatically reversed. Restore from your backup:
Terminal
psql "postgresql://postgres:PASSWORD@db.REF.supabase.co:5432/postgres" < backup.sql

WRAPCODERS Cloud Projects

Use the built-in History feature to restore to a previous version. Click the clock icon in the editor to browse and restore past states.

Credits System

ZenBook includes a full promotion credits economy for monetizing boosted content and advertising.

Credit Balance

  • Each user has a promotion_credits record with a balance field
  • Balance shown in Credits page (/credits) and Advertising hub (/advertising)
  • Transaction history in credit_transactions table (type: spend, topup, gift, admin_gift)

Top-Up Methods

Method Description
Credit Packs Users purchase packs (50, 100, 250, 500, 1000 credits) via the Credits page

Credit Notifications

  • Gift Received — in-app notification when someone sends you credits
  • Admin Gift — special notification for admin-gifted bonus credits
  • Spending Confirmation — toast after boosting posts, pages, or listings
  • Low Balance Warning — toast alert when balance drops to ≤10 credits

How Boosting Works

  1. User clicks "Boost" on supported content
  2. Modal displays tier options with credit costs
  3. Credits are deducted from promotion_credits
  4. Transaction logged in credit_transactions
  5. Sponsored post created in sponsored_posts table with start/end dates
  6. Content appears in feeds with "Sponsored" badge during active period
  7. Low balance warning if remaining credits ≤10

Troubleshooting

App redirects to /setup repeatedly

The user_roles table is empty or its RLS policy blocks reads. Ensure at least one admin row exists.

Setup wizard fails to create admin

The setup-admin edge function requires SUPABASE_SERVICE_ROLE_KEY as a secret. Verify it's set in your backend secrets.

Images/logos not loading

Check that the site-assets bucket exists and is public. Verify URLs in site_settings → admin_design.

Realtime not working

Verify tables are added to the realtime publication: ALTER PUBLICATION supabase_realtime ADD TABLE messages;

RLS permission denied

User may not be authenticated or lacks the required role. Check policies with has_role().

Build fails with TypeScript errors

Terminal
npx tsc --noEmit           # See exact errors
rm -rf node_modules/.vite  # Clear Vite cache
bun install && bun run build

Demo login not appearing

Verify VITE_DEMO_MODE=true is in your .env (not DEMO_MODE). Restart the dev server after changing env vars. Ensure the demo accounts exist in Auth.

Edge function returns 404

The function may not be deployed. Run supabase functions deploy function-name or redeploy via your WRAPCODERS Cloud project.

Credits not deducting / balance unchanged

Verify the user has a row in promotion_credits. If not, insert one with balance: 0. Check RLS policies allow the user to update their own credit balance.

Sponsored post not appearing in feed

Check that is_active = true, start_date ≤ now, and end_date ≥ now. Also verify frequency cap hasn't been exceeded for the viewing user.

FAQ

How do I update to a new version?

Follow the Upgrade & Migrate guide. In short: pull code → install deps → apply migrations → deploy edge functions → build → deploy frontend.

Can I use my own Supabase project?

Yes. Set your Supabase URL and keys in .env, apply all migrations from supabase/migrations/, create the storage buckets, and deploy edge functions.

How do I add a new admin?

An existing admin can assign the admin role via Admin Panel → User Management → click a user → change role to admin.

Is the app mobile-ready?

Yes. ZenBook is fully responsive with a mobile-first design, adaptive sidebar, touch gestures, and swipeable notifications.

Can I customize the branding?

Yes. Go to Admin Panel → Site Design to upload logos, favicon, and set theme colors. Custom CSS/JS can also be injected.

How do I enable/disable features?

Admin Panel → Settings → Features tab. Toggle individual platform features on/off.

Where is user data stored?

PostgreSQL database via Supabase. Files in Supabase Storage buckets. All data is protected by Row-Level Security policies.

How do I give users credits?

Admins can gift credits from Admin Panel → User Management → select user → Gift Credits. Users can also buy credit packs from /credits or receive gifts from other users.

How do I manage ads as an admin?

Admin Panel → Advertisements lets you manage 6 HTML ad slots (header, sidebar, footer, 3 in-feed). Users self-manage sponsored posts from /advertising.

How does demo mode work?

Set VITE_DEMO_MODE=true in .env to show a quick login panel with 3 pre-configured accounts (User, Moderator, Admin). Remove or set to false for production. See Demo Mode.
